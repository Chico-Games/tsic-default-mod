# com.chicogames.default: the base game's content mod

This folder is the game's default mod and the single source of truth for every gameplay
definition, screen, theme, script, icon and font. It is a git submodule of the game checkout
(`Chico-Games/tsic-default-mod`, branch `beta`) shared with the map editor and the mod maker,
so a change here is **two commits**: commit and push inside this folder, then bump the pointer
in the game repo. From the game checkout, `Scripts/commit-defs.ps1 "<message>"` does both.
Packaged builds take the **committed** tree (`git archive HEAD`), never the working copy.

Everything is loose JSON or a plain file; nothing here is a `.uasset`. Folder names are a
convention, not a rule: the loader reads every `.json` under the mod, resolves `class` by
reflection, and the two-letter suffix on the file name says what kind of thing it is.

## Definitions

`<domain>_definitions/` holds items (`ID_*`), furniture (`FD_*`), recipes (`RD_*`), layouts
(`LYD_*`), loot (`LD_*`), biomes (`BD_*`), enemies, input behaviours (`BH_*`), hotkeys (`HK_*`),
input situations (`SIT_*`), skills (`SKL_*`) and the rest. The game's `.claude/CLAUDE.md`
("Definitions Are JSON") lists the prefixes and suffixes. `maps/` holds the JSON-RLE worlds.
`data/changelog.json` is generated by `Scripts/changelog.ps1` in the game repo and feeds the
welcome bulletin; never hand-edit it.

## UI: JSON screens, themes and Lua

All screen UI is data in this mod, rendered by the game's native component library on
UMG/Slate. There is no HTML, no JavaScript and no widget Blueprint on the path.

| Folder | Files | Guide |
|---|---|---|
| `ui_definitions/` | `UI_<Name>_SC.json` screens and overlays, `UI_Hud<Name>_HD.json` HUD layers, `UI_Default_TH.json` the theme | `docs/ui-theme-guide.md` in the game repo |
| `script_definitions/` | `SCR_<Name>.json`: the handle for a Lua script (entry, side, capabilities, hooks) | `docs/modding/lua-api.md` §7 |
| `scripts/` | Lua 5.4: `rules/` runs on the host, `ui/` on every machine, `terminal/` the terminal programs | `docs/modding/lua-api.md` |
| `terminal_programs/` | `TP_<id>.json`: a terminal program's tier, icon and entry script | |
| `icons/` | item thumbnails (`icons/<id lowercase>.png`, referenced as `mod:icons/<id>`), `icons/ui/` the UI's own glyphs, `icons/parts/` character-part thumbnails | |
| `fonts/` | the faces the theme ships (`mod:fonts/<Face>`), with `NOTICE.txt` | |

How the pieces connect:

- A screen is a widget tree (`panel`, `text`, `image`, `button`, `toggle`, `slider`,
  `dropdown`, `list`, `progressring`, `progressbar`, `tabbar`, `actionbar`, `toaststack`,
  `fade`, `textfield`, `worldmarker`) whose properties bind to the `UI.*` gameplay messages
  the screen declares in `uses`, and whose events publish `UI.Cmd.*` messages. Copy the shape
  of `UI_PauseMenu_SC.json`, `UI_Settings_SC.json` or `UI_HudHotbar_HD.json`.
- Every colour, font, size, spacing, radius and duration is a token in `UI_Default_TH.json`;
  a screen names a `style` and never a literal. Fonts enter through the theme's `assets.fonts`
  block (`file` in this mod, `fallback` an engine asset).
- `mod:icons/ui/<name>` and `mod:fonts/<Face>` are paths relative to the mod root with no
  extension; the game imports every image and font file in a mod at load. The same path in a
  later mod replaces it for every screen at once.
- A screen may carry `"script": "SCR_X"` or `"script": "mod:scripts/ui/x.lua"` for logic the
  binding grammar cannot express; `scripts/rules/time.lua` (declared by
  `script_definitions/SCR_TimeRules.json`) is the day/night resolver the host's clock calls.
- `mod.json` declares what this mod may do: `"capabilities": ["rules"]` and
  `"scripts": { "rules": "scripts/rules/time.lua" }` today. The vocabulary is closed
  (`gameplay`, `ui`, `rules`, `cheats`, `console`, `network`) and an unknown name fails the load.

Working loop in PIE: edit, `Ui.Reload` (screens, themes, icons, fonts rebuild in place;
`Lua.Reload <modid>` for scripts), `Ui.Screen <Name>` to open a screen, `Ui.Fixture` and
`Ui.Screenshot` for the parity captures under `docs/ui-parity/`. A definition that fails to
compile is disabled with an `Error` naming the file; the rest of the pack loads.

`web/` is a **reserved name** for one release: a mod that still ships one gets a `Warning`
naming it and the folder is ignored. This mod has no such folder; the reservation is dropped
in the release after the cutover.

## Rules that bite

- Item icons are generated, not hand-authored: `Scripts/icon-gen/` in the game repo renders
  them from meshes, `Scripts/import-doodle-icons.mjs` imports hand-drawn placeholders. Both
  copy into `icons/` and patch the JSON `thumbnail` field.
- One copy. The game, the editors and the tests all read this folder directly; do not copy a
  definition anywhere else.
- Commit here before packaging, or the package ships without the change.
- Never mention an AI assistant in a commit, a comment or a file.
